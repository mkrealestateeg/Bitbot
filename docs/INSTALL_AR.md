# دليل تثبيت Khtb Lab بالعربي

## قبل البدء
هذه نسخة مستقلة عن مستودع Khtp الحالي. لا تستبدل ملفات المشروع القديم. الوضع الافتراضي محاكاة محلية PAPER، ولا يتم إرسال أوامر تداول للمنصة في هذه النسخة.

## التشغيل على جهازك أو سيرفر Linux

1. ثبّت Python 3.11 أو أحدث.
2. ارفع المجلد إلى مستودع GitHub جديد باسم `khtb-lab`.
3. على السيرفر استنسخ المستودع وثبّت الاعتماديات:

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   pip install -e '.[test]'
   cp .env.example .env
   ```

4. أنشئ بوت Telegram جديدًا عبر `@BotFather`، ثم ضع التوكن في `.env`.
5. ضع رقم المستخدم الرقمي في `TELEGRAM_ALLOWED_USER_IDS`. إذا تركته فارغًا فلن يقبل البوت أوامر التحكم.
6. اترك الإعدادات التالية كما هي في البداية:

   ```dotenv
   TRADING_ENV=paper
   TRADING_MODE=MANUAL
   ENABLE_EXCHANGE_ORDERS=false
   DEMO_TRADING_ARMED=false
   LIVE_TRADING_ARMED=false
   ```

7. اختبر وشغّل:

   ```bash
   pytest -q
   python main.py
   ```

## الأوامر الأساسية

- `/start` للمساعدة
- `/status` للحالة
- `/coins` للعملات
- `/coin_add FET/USDT:USDT` لإضافة عملة
- `/scan` لتحليل السوق
- `/mode AUTO` لتفعيل المحاكاة التلقائية فقط
- `/profile SAFE` أو `/profile ADVENTURER`
- `/open SYMBOL LONG ENTRY STOP TARGET` لتسجيل صفقة ورقية يدوية
- `/closeall` ثم `/closeall confirm` لإغلاق الصفقات الورقية
- `/trades` و`/stats`

## تنبيه مهم
يدعم المشروع تنفيذ أوامر Bitget UTA في Demo وLive، لكن إرسالها معطّل افتراضيًا. تُقرّب الكمية وأسعار الحماية حسب دقة السوق؛ يُرسل أمر الدخول أولًا، وبعد تأكيد تنفيذه يرسل البوت أمر حماية TPSL منفصلًا ويتحقق من ظهوره ضمن الأوامر النشطة. قبل كل دورة مسح في Demo/Live، يطابق البوت المراكز المفتوحة وأحجامها وحمايتها مع سجل الصفقات؛ أي مركز غير معروف أو استجابة غير قابلة للتحقق توقف فتح صفقات آلية جديدة لذلك المسح، ولا تغلق المراكز تلقائيًا. إذا تعذّر تأكيد الحماية، ينبه البوت إلى أن المركز مفتوح وغير محمي. اختبر هذا المسار يدويًا في Demo وتحقق من المركز وأوامر الحماية على Bitget قبل التفكير في تفعيل Live؛ نجاح الاختبارات المحلية لا يثبت قبول المنصة للأوامر في حسابك.

ينشئ تيليجرام رسالة متابعة قابلة للتحديث مستقلة لكل صفقة ومستخدم مسموح، وتتضمن السعر وPnL تقديريًا قبل الرسوم والتمويل ومستويي SL/TP وزر إغلاق خاصًا بالصفقة. يُحدّث السعر حسب فترة المسح، ويبقى TP1 عند 1R تنبيهًا فقط دون خروج جزئي. في صفقات DEMO/LIVE المسجلة والمصالحة، يبدأ التتبع البنيوي للوقف عندما تصل حركة السعر المواتية إلى 1R محسوبة من مخاطرة الوقف الأولية المحفوظة عند فتح الصفقة؛ لذلك لا تتغير عتبة التفعيل بتغير الرافعة أو الهامش أو الوقف الحالي بعد تعديله. بعدها يتبع الوقف قيعان/قمم ارتداد مؤكدة من شموع مغلقة مع هامش أمان مبني على ATR، ولا يتحرك إلا في اتجاه تقليل المخاطر وحماية الربح. يبقى الهدف البنيوي المسجل TP2 افتراضيًا. عند بلوغ 90% من المسافة إليه، لا يُزال هدف Bitget إلا بعد تأكيد بقاء وقف الخسارة الكامل نشطًا، ثم يستمر التتبع بعد تجاوز TP2. إذا لم يتوفر ارتداد مؤكد يحقق وقفًا رابحًا، تبقى حماية SL/TP الحالية كما هي. تُحفظ مرحلة الإدارة ومستويات الحماية عبر إعادة التشغيل، وأي حالة ملتبسة أو تعديل غير مؤكد يوقف إدخالات AUTO الجديدة؛ ولا يدير البوت المراكز غير المسجلة تلقائيًا. عند الإغلاق التلقائي أو اليدوي تُحدّث رسالة الصفقة بملخص ونتيجة تقديرية. الإغلاق الفردي من تيليجرام متاح في وضع one-way فقط، ويتحقق البوت من اختفاء المركز على المنصة قبل تسجيله مغلقًا؛ أما hedge mode فيُرفض فيه زر الإغلاق الفردي لتجنب إغلاق مركز آخر على الرمز نفسه.

## التعلم المحلي من الصفقات
يحفظ البوت لقطة ميزات مرقمة الإصدار للصفقات الجديدة، ويدرّب نموذجًا محليًا بسيطًا من الصفقات المغلقة غير المتعادلة في SQLite. بيانات PAPER وDEMO وLIVE منفصلة، ولا يظهر تقدير إلا بعد 30 صفقة مؤهلة على الأقل، بينها 8 رابحة و8 خاسرة. الصفقات القديمة التي لا تحتوي على لقطة الميزات الجديدة لا تدخل التدريب. التقدير غير مُعاير ولم يُتحقق منه على بيانات مستقلة، لذلك لا يُعد توقعًا موثوقًا؛ وهو استشاري فقط ولا يغيّر قبول الصفقة أو حجمها. لا تُرسل بيانات التداول إلى Gemini أو أي خدمة خارجية. احتفظ بمسار `DB_PATH` على Volume دائم في Railway لاستمرار البيانات والنموذج بعد إعادة التشغيل.
